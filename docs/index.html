Kubernetes operator · karkive.io/v1alpha1

You declare a Backup.
KArkive runs the archive.

Scheduled logical backups and restores, in-cluster. Each CR becomes a CronJob whose pod dumps, compresses, GPG-encrypts and syncs to S3, and runs the same pipeline in reverse to restore.

Secrets stay yours

The operator never creates or mutates a Secret. It only reads the one you name in spec.secretRef.

Shell you can read

Every stage is a short POSIX script in its own container. No agent in your database, no custom format.

Standard artifacts

Dumps are plain pg_dump, mysqldump, RDB or tar, gzip and GPG. You can restore without KArkive.

Uploads are not undone

S3 retention prune is best effort: a flaky delete is retried and logged, never a failed backup.

How it works

A CR. Owned objects. A pipeline in one pod.

The controller never shells out. It reconciles owned resources; the Job pod runs the stages, one container each, handing off through marker files on a shared volume. If one stage fails, the others stop.

  1. 1Backup / Restore CRAdmitted by validating webhooks
  2. 2KArkive reconcilesStatus, metrics, owner refs
  3. 3ConfigMap · PVC · CronJobNamed karkive-backup-<name>
  4. 4Pipeline podOne container per stage
  1. cleanupClears markers, prunes local dumps past localRetentionDaysbusybox
  2. dumppg_dump, mysqldump, redis-cli --rdb or tar of a PVCengine image
  3. compressgzip of the dump or archivebusybox
  4. encryptSymmetric GPG with gpg_passphrasegpg
  5. s3-syncMirror to S3, then prune objects past retentionDaysminio/mc

Set spec.s3.enabled: false to skip s3-sync and keep encrypted dumps in retained/ on the PVC.

  1. cleanupClears the workdir and markersbusybox
  2. fetchNamed object, or the newest dump with useLatestBackupAsFallbackminio/mc
  3. decryptGPG with the same passphrasegpg
  4. extractgunzip to a plain dumpbusybox
  5. restorepsql, mariadb, or REPLICAOF from an ephemeral Redisengine image

Restore reads S3 and GPG keys from secretRef and target credentials from a separate engine Secret.

CronJob default

A new Job pod each run. Simple, and fine when the volume attaches quickly.

CronJobWithVolumeHolder

A pause Deployment keeps an RWO claim attached to one node; Job pods land beside it with pod affinity.

API

Write YAML you already know.

Backup and Restore are namespaced CRs. Short names kbackup / bak and krestore / res.

Kind-prefixed names
Owned objects are karkive-backup-<name> and karkive-restore-<name>, so a Backup and a Restore can share a name.
Ready is not last job
status.phase means owned resources are in place. The last run is the BackupSucceeded / RestoreSucceeded condition.
Manual runs
Suspend the schedule and keep the CronJob, then kubectl create job --from=cronjob/… when you mean it.
apiVersion: karkive.io/v1alpha1
kind: Backup
metadata:
  name: app-postgres
spec:
  engine: postgres
  schedule: "0 2 * * *"
  database:
    host: postgres.example.svc
    name: app
  s3:
    endpoint: https://s3.example.com
    bucket: backups
    path: app/pgdump
    retentionDays: 14
  secretRef:
    name: backup-app-postgres
apiVersion: karkive.io/v1alpha1
kind: Restore
metadata:
  name: app-postgres
spec:
  engine: postgres
  schedule: "30 2 * * *"
  suspend: true  # run on demand
  database:
    host: sandbox.example.svc
    name: app
  s3:
    endpoint: https://s3.example.com
    bucket: backups
    path: app/pgdump
  secretRef:
    name: restore-app-postgres
  postgresSecret:
    name: sandbox-postgres
  useLatestBackupAsFallback: true
apiVersion: v1
kind: Secret
metadata:
  name: backup-app-postgres
type: Opaque
stringData:
  username: app
  password: change-me
  s3_access_key: change-me
  s3_secret_key: change-me
  gpg_passphrase: change-me

Engines

Three logical dumps and a file archive. One CR shape.

PostgreSQL

pg_dump in, psql out, on CloudNativePG images. Detects TimescaleDB, and can strip pgAudit DDL on restore.

backuprestore

MariaDB

mysqldump with utf8mb4 and hex-blob. Restore recreates the schema and strips GTID and DEFINER noise.

backuprestore

Redis

redis-cli --rdb on backup. Restore loads an ephemeral redis-server and has the target REPLICAOF it.

backuprestore

PVC files

GNU tar of an existing claim, mounted read-only. consumerSelector places the Job beside the pod that owns an RWO claim.

backup

Install

Helm from GHCR.

Current chart 0.2.3. Images publish to ghcr.io/mahdidarabi/karkive, charts to oci://ghcr.io/mahdidarabi/charts/karkive.

helm install karkive oci://ghcr.io/mahdidarabi/charts/karkive \
  --version 0.2.3 \
  -n karkive-system --create-namespace
helm upgrade --install karkive \
  oci://ghcr.io/mahdidarabi/charts/karkive \
  -n karkive-system --create-namespace \
  --set metrics.serviceMonitor.enabled=true \
  --set metrics.prometheusRule.enabled=true \
  --set metrics.grafanaDashboard.enabled=true
# Argo CD / Flux: let cert-manager own the webhook
# certs so each render does not rotate the CA.
webhook:
  certManager:
    enabled: true

  1. Before you start

    Helm 3 with OCI support and permission to install CRDs. cert-manager only if the webhook uses it; Prometheus Operator is optional.

  2. Verify

    kubectl get deploy -n karkive-system
kubectl get crd backups.karkive.io \
  restores.karkive.io

  3. Declare

    Apply a Secret and a Backup in your app namespace, then watch kubectl get bak. Samples live in config/samples.
