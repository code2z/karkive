Kubernetes operator · karkive.io/v1alpha1

You declare a Backup.
KArkive runs the archive.

Scheduled logical backups and restores, in-cluster. Each CR becomes a CronJob whose pod dumps, compresses, encrypts with GPG or age and uploads to S3 with rclone, streamed in a single pipe or one container per stage, and runs the same pipeline in reverse to restore.

Secrets stay yours

The operator never creates or mutates a Secret. It only reads the one you name in spec.secretRef.

Shell you can read

Every stage is a short shell script, in its own container or chained in one Stream pipe. No agent in your database, no custom format.

Standard artifacts

Dumps are pg_dump, mysqldump, RDB or tar, then zstd or gzip and GPG or age. You can restore without KArkive.

Uploads are not undone

S3 retention prune is best effort: rclone retries a flaky delete, then logs it. It never fails a backup.

How it works

A CR. Owned objects. A pipeline in one pod.

The controller never shells out. It reconciles owned resources; the Job pod runs the pipeline. In Stream mode (the default) one container pipes the whole run straight to S3. In Stage mode (opt-in with spec.pipeline.mode: Stage) each stage is its own container, handing off through marker files on a shared volume; if one stage fails, the others stop.

  1. 1Backup / Restore CRAdmitted by validating webhooks
  2. 2KArkive reconcilesStatus, metrics, owner refs
  3. 3ConfigMap · PVC · CronJobNamed karkive-backup-<name> or karkive-restore-<name>
  4. 4Pipeline podOne Stream pipe, or one container per stage
  1. cleanupClears old run dirs and local dumps past localRetentionDaysrunner
  2. dumppg_dump --format=custom (or directory --jobs), mariadb-dump, redis-cli --rdb - or tarrunner
  3. compresszstd inside pg_dump; zstd -T0 for the other enginesrunner
  4. encryptgpg with gpg_passphrase, or age to the public key in age_recipientrunner
  5. uploadrclone rcat multipart into S3, then best-effort prune past retentionDaysrunner

Stream is the default spec.pipeline.mode: one container, dump | compress | encrypt | rclone rcat, with no plain dump on disk. Tune it with pipeline.jobs and pipeline.compressionLevel (zstd 1–19).

  1. fetchrclone cat of the named or newest objectrunner
  2. decryptgpg -d, or age -d with the private key in age_identityrunner
  3. decompresszstd, or gunzip for Stage objects; Postgres dumps stay compressed for pg_restorerunner
  4. loadpg_restore --jobs, streamed into mariadb, or an in-pod redis-server the target REPLICAOFsrunner
  5. analyzePostgres: vacuumdb --analyze-only, TimescaleDB ALTER EXTENSION UPDATErunner

A Stream Restore also reads Stage objects (*.gz.gpg / *.gz.age), so switch the Restore first and the Backup later. A Stage Restore cannot read Stream objects.

  1. cleanupClears markers, prunes local dumps past localRetentionDaysbusybox
  2. dumppg_dump, mysqldump, redis-cli --rdb or tar of a PVCengine image
  3. compressgzip of the dump or archivebusybox
  4. encryptSymmetric GPG with gpg_passphrase, or agegpg / age
  5. s3-syncrclone copy to S3, then rclone delete --min-age past retentionDaysrclone

Stage is opt-in with spec.pipeline.mode: Stage. Set spec.s3.enabled: false to skip s3-sync and keep encrypted dumps in retained/ on the PVC.

  1. cleanupClears the workdir and markersbusybox
  2. fetchNamed object, or the newest dump by S3 LastModified with useLatestBackupAsFallbackrclone
  3. decryptGPG with the same passphrase, or agegpg / age
  4. extractgunzip to a plain dumpbusybox
  5. restorepsql, mariadb, or REPLICAOF from an ephemeral Redisengine image

Restore reads S3 keys and the decryption key from secretRef and target credentials from a separate engine Secret.

CronJob default

A new Job pod each run. Simple, and fine when the volume attaches quickly.

CronJobWithVolumeHolder

spec.runtime.mode: CronJobWithVolumeHolder: a pause Deployment, karkive-backup-<name>-holder, keeps an RWO claim attached to one node; Job pods land beside it with required pod affinity. Needs persistence; Ready waits for the holder.

API

Write YAML you already know.

Backup and Restore are namespaced CRs. Short names kbackup / bak and krestore / res.

Kind-prefixed names
Owned objects are karkive-backup-<name> and karkive-restore-<name>, so a Backup and a Restore can share a name.
Ready is not last job
status.phase means owned resources are in place. The last run is the BackupSucceeded / RestoreSucceeded condition.
Stream or Stage
spec.pipeline.mode defaults to Stream, one container from the per-engine runner image. Stage (one container per stage) is opt-in. Same Secret keys either way.
S3 is optional
spec.s3.enabled: false keeps encrypted dumps in retained/ on the PVC and needs no S3 keys or endpoint.
Manual runs
Suspend the schedule and keep the CronJob, then kubectl create job --from=cronjob/… when you mean it.
apiVersion: karkive.io/v1alpha1
kind: Backup
metadata:
  name: app-postgres
spec:
  engine: postgres
  schedule: "0 2 * * *"
  database:
    host: postgres.example.svc
    name: app
  s3:
    endpoint: https://s3.example.com
    bucket: backups
    path: app/pgdump
    retentionDays: 14
  secretRef:
    name: backup-app-postgres
  pipeline:
    mode: Stream        # default; Stage is opt-in
    jobs: 4             # pg_dump --jobs
    compressionLevel: 3 # zstd 1-19
apiVersion: karkive.io/v1alpha1
kind: Restore
metadata:
  name: app-postgres
spec:
  engine: postgres
  schedule: "30 2 * * *"
  suspend: true  # run on demand
  database:
    host: sandbox.example.svc
    name: app
  s3:
    endpoint: https://s3.example.com
    bucket: backups
    path: app/pgdump
  secretRef:
    name: restore-app-postgres
  postgresSecret:
    name: sandbox-postgres
  useLatestBackupAsFallback: true
  pipeline:
    mode: Stream  # reads Stage objects too
    jobs: 4       # pg_restore --jobs
apiVersion: v1
kind: Secret
metadata:
  name: backup-app-postgres
type: Opaque
stringData:
  username: app
  password: change-me
  s3_access_key: change-me
  s3_secret_key: change-me
  gpg_passphrase: change-me

Engines

Three logical dumps and a file archive. One CR shape.

Stream mode (the default) runs one image per engine, ghcr.io/code2z/karkive-runner-<engine>, with the client tools, zstd, gpg, age and rclone inside. Override it per CR with spec.images.runner. Stage mode runs upstream images: CloudNativePG PostgreSQL 18.4, MariaDB 10.6, Redis 7.4, Debian trixie-slim, BusyBox, vladgh/gpg and rclone/rclone.

PostgreSQL

Stream: custom or directory format with zstd, pg_restore --jobs, then vacuumdb --analyze-only. Stage: plain pg_dump in, psql out. TimescaleDB loads at the source version from a .meta sidecar; pgAudit DDL can be stripped.

backuprestore

MariaDB

Stream: mariadb-dump | zstd, loaded into any target database name. Stage: mysqldump with utf8mb4 and hex-blob; restore recreates the database and strips GTID and DEFINER noise.

backuprestore

Redis

redis-cli --rdb on backup. Restore loads an ephemeral redis-server on :6380 and has the target REPLICAOF it, so the target must reach the Job pod.

backuprestore

PVC files

engine: pvc: GNU tar of an existing claim, mounted read-only, with path and excludes. consumerSelector places the Job beside the pod that owns an RWO claim. Restore is manual: gpg -d | zstd -d | tar -x (or age -d).

backup

Install

Helm from GHCR.

Current chart 0.4.1. The operator image publishes to ghcr.io/code2z/karkive, Stream runners to ghcr.io/code2z/karkive-runner-<engine>, charts to oci://ghcr.io/code2z/charts/karkive.

helm install karkive oci://ghcr.io/code2z/charts/karkive \
  --version 0.4.1 \
  -n karkive-system --create-namespace
helm upgrade --install karkive \
  oci://ghcr.io/code2z/charts/karkive \
  --version 0.4.1 \
  -n karkive-system --create-namespace \
  --set metrics.serviceMonitor.enabled=true \
  --set metrics.prometheusRule.enabled=true \
  --set metrics.grafanaDashboard.enabled=true
# Argo CD / Flux: let cert-manager own the webhook
# certs so each render does not rotate the CA.
webhook:
  certManager:
    enabled: true

  1. Before you start

    Helm 3 with OCI support and permission to install CRDs. cert-manager only if the webhook uses it; Prometheus Operator is optional.

  2. Verify

    kubectl get deploy -n karkive-system
kubectl get crd backups.karkive.io \
  restores.karkive.io

  3. Declare

    Apply a Secret and a Backup in your app namespace, then watch kubectl get bak. Samples live in config/samples.
